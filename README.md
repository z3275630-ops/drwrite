# Drwrite · 墨

本地优先的长篇小说写作台。稿件与资料保存在你的电脑上；使用在线 AI 时，本次所需的正文和资料会发送到你选择的服务商。本地 Ollama 可在本机处理。

### v0.7.2：保存失败也守住当前稿件

- 保存失败会阻止切章、回书架、备份、导出和正常退出，错误会驻留，可重试或把当前正文另存为 TXT。
- 保存按版本排队，较早请求完成不会把后来输入的内容标成已保存；文件替换成功前保留原文件。
- 新快照同时保存目录、正文和作品资料，含完整性清单；恢复失败回滚，恢复中断后重新打开作品会先回滚。旧快照明确标为“仅正文与目录”，恢复时保留当前资料。
- 长章续写带入最新结尾；提案中可展开核对实际上下文片段。
- 连接测试结果驻留、成功导出的位置会记忆；本章面板可直达伏笔、时间线与剧情总览，长章滚动时也能看到保存状态。

灵感来自对 [Loomworld 织境](https://loomworld.cn) 的深度拆解（交互与架构理念的学习，非代码或素材的复制），向先行者致意。

## 它能做什么

**写作台**
- 书架管理多本书；一本书 = 一个普通文件夹（`book.json + chapters/ + entities/ + snapshots/`），拷走即备份
- 所见即所得编辑器，停笔 0.8 秒自动保存（临时文件原子写入），Ctrl+S 立即保存，**关窗前自动落盘最后一笔**
- **正文顶栏**：点击章节名直接改、`‹ ›` 前后翻章、右侧实时字数；**撤销 / 重做按钮**就在顶栏（Ctrl+Z / Ctrl+Y）
- 章节管理（自动中文数字命名 / 重命名 / **拖拽排序** / 删除）、**分卷**（卷中分组、拖入即归卷，导出自动带卷名）
- 字数统计（今日 / 全书 / 连更天数 / 日更目标进度条）
- 完整作品快照（目录＋正文＋资料，含人物/设定/伏笔/素材/聊天与文件校验；恢复前自动留底，手动保留 20 份；**每天第一次保存自动做一份快照**，保留 7 份）。浏览器开发预览不提供磁盘快照，请用桌面版。
- 导出 Markdown / 全书 TXT / 分章 TXT；**素材箱**（灵感速记，一键插入到光标处，选中文本右键可存）
- **专注模式**（隐藏两侧面板，Esc 退出）与**排版设置**（字号 / 行距 / 字体 / 打字机滚动，跨书记忆）

**资料库**（解决"百万字记不住设定"）
- 人物卡：五档层级、别名、经历、关系（含反向称呼）、所属势力、**状态演变**（从第几章起断臂/黑化/成为宗主，AI 按当前章取现况）
- 设定词条：世界观/地点/势力/规则/术语/事件；势力是人物归属的真源
- **道具卡**：法宝/信物/金手指，记完整**流转历史**（谁在第几章拿到、交给谁），当前持有人自动推导
- 正文 `@` 引用（人物/设定/道具）；已建卡实体名自动**淡提示**，点击确认才转为关联——识别 ≠ 关联
- 检视器：点击正文引用看卡片、状态、流转与出场章节；**关系图谱**（可拖拽）+ **共演发现**（同章出场≥2次却没画关系的配对，一键去建）
- **地点层级树**：世界→大陆→城市→地点，节点可绑定「地点」词条
- 全书搜索（正文 + 资料含别名）
- **AI 通读建卡**：让 AI 分批读完正文，抽取人物/设定/道具建议，勾选后才建卡（已有卡自动跳过）
- **导入旧书 TXT**：按「第X章」自动分章（UTF-8/GBK 自适应），存量长篇直接搬进来

**AI（BYOK，用你自己的密钥）**
- 任何 OpenAI 兼容接口（DeepSeek / Kimi / 通义 / 本地 Ollama），密钥只存本机
- 选中文字右键：改写 / 扩写 / 缩写 / 润色 / 自定义要求；AI 续写本章
- **全程流式输出**：字到了就落屏（含思考型模型的"思考中"进度），不再干等
- **提案确认卡**：AI 只建议、作者拍板，应用后 Ctrl+Z 一步整体撤销
- 上下文装配：续写按任务带入剧情总览、本章章纲、相关已关联资料、截至本章的待收伏笔与最新前文；片段有长度上限，并非整本书都发送。改写带选区及其邻近前后文。提案可展开查看实际来源。
- **章纲工作流**：动笔前为每章列 5～8 条要点（手写或 AI 起草），续写按纲推进
- **剧情总览**：一键把新章节梗概并入全书滚动摘要，还可批量补全缺失梗概——百万字也不忘开头的伏笔
- AI 一致性巡检：拿着设定和伏笔审读本章，报告边生成边出
- AI 写作顾问：右栏「✦ 写作顾问」，上下文胶囊（本章正文 / 资料卡 / 伏笔 / 剧情总览）随开随关，空会话给四张起手卡，流式回复、可复制；对话存在书里，不改正文

**结构**
- **场景层**：正文里插「◇ 场景」分隔线并命名（双击改名）；时间线、伏笔、本章面板都可精确锚到场景，AI 续写按场景节拍推进
- 时间线：多剧情线，事件锚定章节或**具体场景**与人物
- 伏笔：埋设 / 强化 / 回收章节锚点，状态自动推导（含"埋伏过久"预警）；**跨度视图（甘特图）**一眼看出每个伏笔从埋到收跨了多少章
- **本章面板**（右侧常驻）：本章场景标记、出场人物/道具/设定、待收伏笔、章纲与梗概速览，快捷打开伏笔/时间线/剧情总览

**其它**：深色模式、流派模板（玄幻/都市/科幻/历史/悬疑，预置引导性设定词条）、章节梗概（手写或 AI 概括）。

## 数据形态

```
书库/（默认 文档\Drwrite 书库，可换）
  书名-xxxxxx/
    book.json          书元数据 + 章节目录 + 分卷 + 剧情总览
    chapters/<id>.json 每章一个 Tiptap JSON 文档
    entities/
      characters/      人物卡
      lore/            设定词条
      props/           道具（含流转历史）
      timeline.json    剧情线与事件
      foreshadows.json 伏笔
      locations.json   地点层级树
      chat.json        AI 对话记录
      notes.json       素材箱
      refs.json        正文引用倒排索引（派生，可重建）
  snapshots/         完整快照＋manifest.json（auto- 前缀为每日自动）
```

JSON 全部可读、可 diff、可被任何工具处理——数据主权归作者。

保存和快照可以降低软件故障风险，不能保证硬盘损坏或突然断电时绝不丢失。重要作品请定期将整个书文件夹复制到另一个磁盘。全局 AI 密钥配置不包含在作品快照里。

## 构建

技术栈：Tauri 2 + React 19 + TypeScript + Vite + Tiptap 3（Rust 侧仅做文件与 HTTP 网关）。

```bash
npm install
npm run tauri dev        # 开发
npm run tauri build      # 打包（或 npx tauri build --no-bundle 产出单文件 exe）
```

需要 Node 18+ 与 Rust（msvc 工具链）。
