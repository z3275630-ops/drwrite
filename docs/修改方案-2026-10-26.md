# Drwrite 修改方案：先守住稿子，再让 AI 接得上

日期：2026-10-26（北京时间）

作者：Codex

状态：用户已选择方案 C（防丢＋AI＋易用性）；v0.7.2 已实施、完成本文件列明的桌面验收并交付。文档选定范围先于代码改动落盘。

## 1. 结论与本轮选择

**建议先修保存失败后的防丢保护、完整快照、文件替换，再修长章 AI 续写取错上下文。**

普通输入、长文本保存、正常关窗保存和 AI 提案撤销表现良好，但它们不能证明异常情况下也安全。本轮通过桌面实操复现了“保存失败后切章丢字”和“正文恢复了、人物卡却没恢复”。另通过运行现有上下文函数确认：长章续写带的是章首，最新结尾被截掉。

提问框中的三个范围对应如下，用户选择后先将本文件更新为选定范围，再动代码：

| 方案 | 内容 | 目的 |
| --- | --- | --- |
| A，推荐：防丢＋AI | S1–S3、A1，以及直接相关的文案、验证 | 先能安全写，再让 AI 真正接着最新内容写 |
| B：只修防丢 | S1–S3，以及直接相关的文案、验证 | 收紧本轮范围，先解决稿件可靠性 |
| C：防丢＋AI＋易用性 | S1–S3、A1、U1–U3 | 在 A 的基础上，补连接反馈、导出位置和功能入口 |

已选择：**C：防丢＋AI＋易用性**。实施 S1–S3、A1、U1–U3，并更新说明和验收记录。选择由用户在提问框明确回复。

## 3. 实测证据与判定

### E1：普通正文保存，通过

新建空白测试书，用界面输入三段中文故事。界面统计 118 字，Ctrl+S 后磁盘 `book.json` 与章节文件相符，产生每日自动快照。

判定：支持前一棒“普通写作能落盘”的结论；不支持扩大为异常保存也安全。

### E2：长文输入与输入后立即切章，通过

第二章经界面输入 16,404 个字符、251 段（250 段故事＋尾标记），应用字数为 15,760。再输入 `【切章前最后一笔】`，紧接着点第一章。磁盘第二章仍有完整尾标记与最后一笔，章字数为 15,769。

判定：这个规模和操作下未发现末尾丢失；没有测量帧率或按键延迟，不能据此承诺百万字流畅。切章后的 Ctrl+Z 没有把第二章内容倒灌进第一章。

### E3：真实 AI 提案应用、撤销、重做，通过

第一章 118 字时点击 AI 续写，真实响应显示输入约 267、输出 590 tokens，提案展示 777 个字符。应用后正文统计 871 字；Ctrl+Z 一步回到 118 字；Ctrl+Y 恢复到 871 字。

判定：保留现有提案制与整段撤销。字符数与应用字数统计口径不同，不把数值差异误报为丢字。

### E4：正常输入后立即关窗、重启，通过

追加 `【关窗前最后一笔-1026】` 后立即 Alt+F4，磁盘含该标记，第一章 882 字。重开程序并打开本轮测试书，正文仍包含标记；两章总计 16,651 字。

判定：普通正常退出的最后一笔保护有效；本轮没有以这条结果证明强杀、保存超时或失败退出安全。

### E5：快照恢复出现正文与资料的时点分离，已复现

1. 原正文 118 字；建立人物阿澜，性格为“快照前：谨慎，只相信亲眼见到的证据”。
2. 点击立即备份，得到手动快照 `20261026-103829`。
3. 将性格改为“快照后：鲁莽，已经信任河底的声音”，正文追加 `【快照后正文】`，变成 140 字。
4. 恢复上述手动快照。确认框写的是“覆盖当前全部内容”。
5. 正文回到 118 字、追加标记消失；人物卡和磁盘人物 JSON 仍为“快照后：鲁莽……”。
6. 磁盘快照只有 `book.json` 与 `chapters/`，没有 `entities/`。

判定：当前备份面板本来就写明“目录＋章节”，但恢复确认框的“全部内容”含糊，且对作者而言缺少资料的一致恢复。不是已经丢掉人物文件，而是正文和作品记忆回到不同时间点。

源码：`src/lib/library.ts` 的 `createSnapshot`（约 356 行）、`restoreSnapshot`（约 387 行）；`src/components/Editor.tsx` 的恢复确认框及 `doRestore`（约 937 行）。

### E6：保存失败后切章导致未保存文字消失，已复现

1. 第一章 882 字时，对本轮测试章执行前述临时目录故障注入。
2. 界面输入 `【保存失败时绝不能消失-1026】`，当前正文变为 896 字。
3. Ctrl+S，出现“保存失败：拒绝访问。（os error 5）”；已存仍为 882。
4. 点击第二章，程序继续切换，未要求先解决保存失败。
5. 移除故障注入，再回第一章，界面恢复为 882 字；标记消失。磁盘也没有该标记。

判定：这是实际复现的异常丢字问题。模拟的原因是临时文件不可写，不声称已经模拟了真实磁盘满额等所有原因。

根因：`flushSave`（`Editor.tsx` 约 224 行）在 catch 中提示错误、恢复 dirty，却不向调用方返回失败；`switchChapter`（约 684 行）await 后照常加载新章，`loadChapterInto` 又清空脏状态。退出、导出、备份等调用同一函数的路径应一并审查，不能只堵住切章按钮。

### E7：长章续写截掉最新结尾，现有函数运行确认

对现有 `buildAiMessages` 做无网络、无写书操作的函数验证：构造 6,019 字符，开头为 `【开头记号】`，结尾为 `【最新结尾：阿澜已到沙漠】`。结果：`headIncluded=true`，`latestEndingIncluded=false`。

根因：`Editor.tsx` 把整章作为 `chapterTail` 传入；`assembler.ts` 约 22 行的 `clip` 是 `slice(0, max)`，约 132 行将它用于“本章前文”，续写只保留章首 2,000 字符。

判定：不能把短章续写质量推成所有长章都能贴着最新结尾。写作顾问使用 `.slice(-800)`，与续写不是同一条上下文路径，不应混为一谈。

### E8：先删旧文件再替换，源码确认的风险

`src-tauri/src/lib.rs` 的 `write_text_file`（约 28 行）先写固定 `.tmp`，随后 `remove_file` 删除目标，最后 `rename`。这两个步骤之间存在原文件不在原路径的窗口，替换失败也可能只剩临时文件；固定临时文件名还需要处理并发写入。

判定：撤回“当前已实现严格原子替换”的表述。本轮未在删除与重命名之间强杀来制造丢稿，不把源码风险写成已实测发生。

## 5. 详细实施方案

### S1 · 保存失败不能让稿子被切走（最高优先级）

**动机：** E6；这是稿件损失问题，不是提示文案问题。

**文件：** `src/components/Editor.tsx`、`src/lib/library.ts`；必要时抽出 `src/lib/saveCoordinator.ts` 与小型错误状态组件，避免继续扩张 Editor。涉及状态样式时改 `src/styles.css`。

**方案：**

1. 保存必须返回明确的成功/失败结果，或向调用方抛出错误。区分“没有待保存变更”与“有进行中的保存”，后者需要等待。
2. 按作品协调写入，保存请求捕获明确的章节 ID、文档版本与内容；等待正在进行的保存，写入期间又有输入则继续保存最新版本。旧请求完成不能把新变更标为已保存。
3. 切章、回书架、新建/删除章节、快照、恢复、导出、正常退出都经过同一保存门槛。保存失败时留在原章，不清空草稿与撤销历史，不生成“已备份/已导出”的成功提示。
4. 错误在界面驻留，提供“重试保存”“另存稿件”与“继续编辑”；仅使用临时 toast 不足够。
5. 取消当前“2.5 秒一到照样退出”的兜底行为。超时回到可操作的失败状态，不能自动当成成功或直接销毁窗口。
6. 正文保存与目录统计一致更新；索引可重建，索引失败应有可见提示或稍后重建，不应伪装成正文丢失。

**验收：**

- 重跑 E6：出现拒绝访问后，点第二章、回书架、新章、导出、备份、关窗，均不得丢掉原章未保存标记。
- 移除注入，点重试；磁盘与界面都含标记，之后可正常切章、退出。
- 保存进行中追加 A/B/C 三段并连续 Ctrl+S，最终磁盘包含三段；完成较早的请求不能把较新的草稿清为已保存。
- 正常保存仍保留约 0.8 秒防抖，输入不被锁死；E1–E4 回归通过。
- 错误时 Ctrl+Z 仍能撤销本章操作，不把其他章倒灌进来。

**风险与回滚：** 保存协调改变所有离开编辑器的路径，必须统一审查调用点。独立提交；回滚程序时保留所有稿件与救援文件，禁止通过回滚删除书库数据。

### S2 · 可靠替换文件，旧稿不能提前被删

**动机：** E8；源代码里“Windows rename 不能覆盖”的注释与当前 Rust 标准库说明不符。

**参考与复用：** 优先直接使用 Rust 标准库 `File`、`write_all`、`sync_all`、`std::fs::rename`。官方文档说明目标已存在时替换目标，Windows 使用平台实现；不自行模拟“删除再改名”。这是复用标准库能力，不声称移植了某个完整存储引擎。

**文件：** `src-tauri/src/lib.rs`；需要时拆出小型文件写入模块。默认不新增依赖。

**方案：**

1. 在目标文件同目录创建唯一临时文件，防止固定 `.tmp` 名称互相覆盖；同一目标写入有明确顺序。
2. 完整写入、检查结果并同步文件，再替换目标；替换前不删除目标。
3. 替换失败保留旧文件并报告失败，清理或记录本次唯一临时文件；不能在错误兜底里再退回“先删旧稿”。
4. 合理处理 Windows 文件占用错误。硬件断电耐久性与软件原子替换分开说明，不做绝对防丢承诺。

**验收：**

- Windows 下连续覆盖同一中文路径 JSON，文件始终可解析；成功时为完整新内容。
- 模拟写临时文件失败、目标被占用、重命名失败，旧目标仍存在且内容不变，调用方收到失败。
- 并发写同一路径不会混成半份 JSON，也不会误删另一请求的临时文件；最终顺序符合保存协调策略。
- Rust 针对失败路径的测试通过；实际桌面回归 E1–E4。

**风险与回滚：** `sync_all` 可能增加耗时，实测后决定是否对正文和元数据统一使用；不能为性能取消错误处理。保持 JSON 书库协议兼容。

### S3 · 一次完整作品快照，以及可恢复的恢复流程

**动机：** E5；备份要覆盖作者积累的作品记忆，恢复不能先销毁唯一可用版本。

**文件：** `src/lib/library.ts`、`src/lib/fs.ts`、`src-tauri/src/lib.rs`、`src/components/Editor.tsx`；按需新建 `src/lib/snapshots.ts`。更新 `README.md`、`docs/DESIGN.md` 的保存与快照说明。

**方案：**

1. 新版快照包含 `book.json`、`chapters/`、`entities/`，即人物、设定、道具、时间线、伏笔、地点、素材与书内聊天等已有书内数据。兼容旧位置的派生索引，恢复后可重建。
2. 不复制 `snapshots/` 自身，不复制全局设置或密钥。增加快照清单：格式版本、创建时间、范围、文件清单与完整性状态。
3. 创建到临时目录，全部复制并校验成功后才作为可恢复快照显示；备份期间等待作品写入队列，确保同一时点。失败不标成功。
4. 恢复前校验所选快照及协议，先生成经过验证的恢复前完整快照；复制到独立暂存区并校验，再切换现用数据。
5. 多个目录的切换不是天然单步事务。需要恢复记录/阶段标记以及启动时继续或回滚的策略；不能复制失败后只留下空 `chapters/`。
6. 成功后重新加载正文、人物、设定、道具、结构、素材和聊天，重建引用。只刷新正文会留下过期的内存资料。
7. 旧快照只有章节时，明确标为“旧版：仅正文与目录”；恢复前解释资料不会回退。不把缺少 `entities/` 的旧快照当成“资料为空”而清空现有资料。
8. 快照命名避免同秒冲突；保留手动 20 份、每日自动 7 份的既有策略，只对完整快照执行轮转，恢复前留底不得在本次恢复完成前被删除。

**验收：**

- E5 的新版快照恢复后正文和人物卡同时回到快照前；重启后仍一致。
- 分别修改伏笔、时间线、道具、素材与聊天，再恢复，全都遵守标注的范围。
- 旧版快照仍可恢复章节，明确警告资料不回退；原有资料不会被清空。
- 破坏测试快照、模拟复制失败、取消或中断恢复，当前作品仍可打开，或启动时能完整回滚；不得先删光当前章节。
- 缺文件/损坏快照不显示为“可正常恢复”；不递归复制快照、不包含密钥。
- 恢复前自动留底能够把作品恢复到恢复前状态，不能只验证备份目录存在。

**风险与回滚：** 新旧快照共存，旧版应用可能不理解新清单。新版目录保持现有基础文件形态；增加可选元数据而不是迁移或清空旧书。必要时回滚程序，保留原书与所有恢复暂存区供检查。

### A1 · 长章续写必须看到最新结尾

**动机：** E7；这是长篇主线能力，不只是 AI 展示优化。

**文件：** `src/lib/assembler.ts`、`src/components/Editor.tsx`；对照 `src/components/ChatPanel.tsx`，必要时抽共享上下文辅助函数。

**方案：**

1. 区分“从开头压缩资料”和“保留最近正文”，不要把同一个 `clip` 用于两种语义。续写明确保留最新 2,000 字符，并在前方提示截断。
2. 选区改写带上靠近选区的前后文，不能拿整章开头代替邻近上下文；保持选区原文完整。
3. 上下文列表必须反映实际发送内容。当前续写装配函数并未接收伏笔清单，不能继续笼统承诺“每次都带全”；若在本轮补入，只带截至当前章的相关待收伏笔，并给出数量/长度上限。
4. 优先最近前文、当前章纲、已确认关联的相关人物卡，之后才压缩较远的摘要。不把未确认的淡提示自动变成持久关联。
5. 简短显示“已带入：本章结尾/章纲/相关资料”等真实来源；展开可核对经过裁剪的片段，不显示密钥。没有装配的项不能显示为已读取。
6. 保留现有提案确认与整段撤销，沿用 ProseMirror/Tiptap 的历史能力；仅在回归发现合并问题时使用现成历史分组接口，不重写撤销系统。

**验收：**

- 重跑 E7，最新结尾标记必须存在、无关开头不再占据本章最近前文预算；短章仍完整保留。
- 在测试长章结尾写出与章首明显不同的新事件，真实续写应能接住新事件；同时直接核对装配文本，不能只凭模型碰巧答对。
- 选区位于章末时，邻近前文来自章末；原文字符不因裁剪丢失。
- 界面显示的上下文来源与实际消息一致；AI 不偷偷改正文；E3 撤销/重做继续通过。
- 没有设置卡或没有 AI 配置时保持现有可用行为，不强制先建卡才能写作。

**风险与回滚：** 模型措辞有随机性，所以结构断言与真实试写两层验证。上下文预算不等于精确 token 计费，展示时区分字符估算与接口返回用量。独立提交，回滚不影响作品数据。

### U1 · AI 测试连接结果驻留（只在 C 中实施）

**依据：** 前一棒压测 §2 踩坑 2；本轮源码确认 `AiSettingsModal.tsx` 只用 toast，`Toast.tsx` 在 2.8 秒后移除。未在本轮打开包含密钥输入的设置窗口重新测试。

**文件：** `src/components/AiSettingsModal.tsx`、`src/styles.css`。

**方案：** 测试结果显示在设置内，包含成功/失败、模型、响应耗时；修改接口或模型后标记旧结果已失效，测试中禁重入，错误文本不回显密钥。无需引入组件库。

**验收：** 成功/失败结果停留 30 秒仍可见；修改模型不保留误导的成功状态；失败后能重试，取消不改已存配置。

**风险与回滚：** 只新增局部状态；不能把“已发请求”等待中写成已连接成功。

### U2 · 导出位置有记忆，取消清楚（只在 C 中实施）

**依据：** 前一棒压测 §2 踩坑 3；本轮源码确认 `saveExportFile` 仅传文件名，分章 TXT 已有入口，不能误说尚无单章导出。

**参考：** 直接复用已安装的 Tauri dialog 插件 `defaultPath`，保留系统另存为对话框。

**文件：** `src/lib/library.ts`、`src/components/Editor.tsx`；如有必要补独立导出偏好字段，沿用配置合并逻辑。

**方案：** 优先上次成功导出的目录，其次当前书库；只有成功写出才记忆。取消不弹成功提示，写失败保留错误与重试入口。单章/全书 MD、TXT 和分章 TXT 都按同一原则处理。

**验收：** 首次默认目录正确；成功选目录后下次回到该目录；取消不产生文件也不改偏好；未保存正文因保存失败时不得导出旧稿并报成功。

**风险与回滚：** 位置设置不得覆盖 AI 配置；不为了改变目录重新读出或记录 API 密钥。

### U3 · 保存状态与结构入口看得见（只在 C 中实施）

**依据：** 本轮 1275×800 实测中，长章滚动时底部字数/操作栏会离开视野；前一棒报告结构功能可发现性弱。本轮没有把屏幕截图造成的中间态当成性能测量。

**文件：** `src/components/Editor.tsx`、`src/components/ChapterPanel.tsx`、`src/components/StructureTab.tsx`、`src/styles.css`。

**方案：**

- 常驻区至少保留保存状态与重试入口，不要求滚到长章最底部才能确认是否保存。
- 右侧本章面板增加明确的“伏笔”“时间线”“剧情总览”快捷入口，复用现有结构页；不重做整个导航。
- 空状态文案指向真实动作，先让作者完成“写一句→建人物→确认关联→回正文”，不加十章教程或新正文节点。
- 界面与 README 准确区分本地保存和在线 AI 请求：使用在线 AI 时必要上下文会发送给用户选择的服务商。不能把“本地优先”写成在线 AI 从不联网。

**验收：** 1275×800 窗口长章首尾都能看见保存状态；三项入口两次点击内可达、可回正文；专注模式退出与快捷键不退化；无 AI 配置仍能完成写作与关联。

**风险与回滚：** 小范围布局改动，保持现有侧栏与正文宽度；不新增统计“质量分”、人物自动层级或强制教程。

## 6. 成熟方案、依赖和不做项

| 部分 | 采用方式 | 适配与约束 |
| --- | --- | --- |

默认无新增第三方依赖。若实施验证发现必须新增依赖，先在本文件写明实际源码、许可证、维护与兼容性证据及接入理由，再决定；不为小改动引入无关架构。

本轮不做地图、3D 书架、排行榜、人物自动层级、节奏综合评分、日历时间轴、剧本节点模式、新账号/订阅、云同步，也不把 AI 当成静默改稿器。

## 7. 实施顺序、回归与交付

1. 用户选定范围后，先更新本文的范围与状态；文档落盘后才改产品代码。
2. S1＋S2 先行，复现保存失败与可重试恢复；按实际修改边界拆小提交。
3. S3 完整快照与恢复，包括旧快照兼容和失败回滚。
4. A/C 执行 A1；C 再执行 U1–U3。
5. 每个实现批次执行 `npm run build`。Rust 改动还执行相应测试与构建检查；无需为纯文案写镜像测试，数据路径和故障行为必须有针对性的自动验证。
6. 重新打包并在真实桌面程序上做 Computer Use 冒烟，不以 Vite 浏览器预览或 TypeScript 检查代替桌面验证。新程序先独立输出，核验后再更新根目录可运行版本；保留旧程序备份。
7. 只用临时书测试，覆盖新书、测试夹具复制件、旧版快照、新版快照。对真实书库不得自动迁移或跑测试。
8. 交付说明写清已修、未修、仍未验证的边界；同步 README 与 DESIGN，不能继续保留已被推翻的原子替换/绝对安全/上下文全带等表述。

这不是“一小时补两个按钮”的修改。S1–S3 涉及保存与恢复链路，应以验收证据而非固定工时决定是否交付。
