# Drwrite · 墨 — 设计思路

> 本文是 Drwrite 的产品与技术设计总纲。改动任何核心行为前先读这里；与本文冲突的新想法，先改本文、达成共识，再改代码。
> 配套阅读：`README.md`（功能与数据形态）、`docs/真写压测-织境vs-Drwrite.md`（2026-10-25 双工具实测）、`docs/loomworld-实操对比-改进建议.md`(P0-P3 改进清单)。

## 1. 一句话定位

**本地优先、AI 深度集成的中文长篇小说写作台**：散文优先的所见即所得写作 + 越写越懂你作品的资料库，网文连载场景特化。稿件与资料本地保存；使用在线 AI 时，只向用户所选服务商发送本次所需上下文。密钥用于该接口认证，不进入作品快照。

## 2. 根源问题

长篇创作的敌人不是没灵感，而是 **记忆衰减 + 重复解释 + 打断**：

- 百万字记不住设定 → 资料库（人物/设定/道具/地点/伏笔/时间线）做"记忆外包"
- 同一段人设反复解释给 AI → 上下文装配器自动带全书记忆
- 频繁跳出写作流 → 键盘优先、零表单、底栏即用

## 3. 对织境 Loomworld 的取舍（学什么，不学什么）

| 织境的做法 | Drwrite 的取舍 | 理由 |
|---|---|---|
| 9 节点剧本范式（场次/角色/对话…） | **不学**。散文优先 + ◇场景分隔 + 后补标记 | 网文是散文不是剧本；织境自己的文档承认小说作者有转换成本 |
| 订阅 + 积分 + 云同步 | **不学**。开源 + BYOK（自带密钥），密钥只存本机 | 本地优先是获客与信任的根；"不登录全功能"是差异卖点 |
| 正文浏览器存储（清缓存丢稿） | **反超**。一本书 = 一个文件夹，JSON 可 diff 可 git | 织境用户在为"防丢"付月费，我们免费且更稳 |
| 教程即注释节点 + 10 章引导 | **要学**（P0） | 实测证明这是冷启动最优解 |
| 层级建议带依据 / 节奏四象限 / 伏笔分类学 / 字段级动态 | **按优先级吸收** | 见改进建议文档 |
| 3D 书架 / 地图 2D3D 双版本 | **不学**（P4 观望） | 投入产出比低，网文场景低频 |

核心共识原则（继承自织境并已验证）：
1. **识别 ≠ 关联**：正文出现实体名只给淡提示（虚线），点击气泡显式确认才建关联。
2. **提案制 AI**：AI 不静默写入正文；续写/改写先出提案，应用后可一步整段撤销（Ctrl+Z）。
3. **防假保存**：底栏实时显示"本章 N 字（已存 M）"，顶栏常驻保存状态；0.8s 防抖 + 版本排队 + 同目录唯一临时文件同步后替换（不先删旧稿）。保存失败保留草稿并阻止切章/离开/备份/导出/退出，允许重试和另存正文。正常关窗等待保存，超时取消关闭，不能强制销毁。每日自动完整快照。
4. **手写内容神圣**：AI 与自动维护只填空（点此起草/补全），不覆盖用户写过的字段。
5. **派生不落库**：字数/出场/待收伏笔等统计永远现算（refs.json 倒排索引），不做第二份真相。

## 4. 数据模型（一本书 = 一个文件夹）

```
书库/（默认 文档\Drwrite 书库，可换位置）
  书名-xxxxxx/
    book.json            书元数据 + 章节目录 + 分卷 + 剧情总览 + dailyStats
    chapters/<id>.json   每章一个 Tiptap JSON 文档（含 entityRef/sceneMark 自定义 mark）
    entities/
      characters/*.json  人物卡：层级/别名/性格/经历(biography[])/状态演变/关系(双向)
      lore/*.json        设定词条（势力是人物归属的真源）
      props/*.json       道具（流转历史，当前持有人推导）
      locations.json     地点层级树（世界→大陆→城市→地点）
      timeline.json      剧情线与事件（锚定章节/场景 + 相关人物）
      foreshadows.json   伏笔（埋设/强化/回收章节锚点 + 状态机 + 预警）
      chat.json          AI 对话记录（存在书里）
      notes.json         素材箱（灵感速记）
      refs.json          正文引用倒排索引（派生，可重建）
    snapshots/           完整作品快照（book.json + chapters + entities + manifest.json；手动 20 / 每日 auto- 7）
```

- **为什么正文用 Tiptap JSON 而非 Markdown**：entityRef（实体引用）/sceneMark（场景锚点）内嵌正文，Markdown 表达不了，会有损转换。Markdown 只做导入/导出格式。
- 引用存稳定 ID 不存文字 → 改名不断链。
- 所有 JSON 可读、可 diff、可被任何工具处理——数据主权归作者。

## 5. 技术架构

- **Tauri 2 + React 19 + TypeScript + Vite + Tiptap 3**；Rust 侧只做文件与 HTTP 网关（不进业务逻辑）。
- 前端结构：`src/components`（UI，Editor.tsx 是最大的编辑器组件）、`src/lib`（领域逻辑：entities/library/assembler/ai/structure…）、`src/extensions`（Tiptap 扩展：entityRef/sceneMark/typewriter/historyKeys）。
- AI：任何 OpenAI 兼容接口 + 本地 Ollama；密钥只存本机设置文件；流式输出；上下文装配器按任务取（剧情总览滚动摘要 / 章纲 / 实体卡 / 伏笔清单 / 场景梗概 / 前文）。
- 界面文案说人话说具体；表单反馈用不占布局的 toast。

3. AI 设置"测试连接"结果一闪而过；导出另存为对话框默认目录是应用目录而非书库。
4. 人物卡层级无"依据"建议；无排行榜；无节奏全景（密度曲线/热力图）。
5. 时间线只有卡片流，无日历刻度轴。
